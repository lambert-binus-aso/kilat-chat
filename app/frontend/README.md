# KilatChat React frontend

The frontend is React + Vite, served through Django's HTML templates and static files. It uses a permanent charcoal-grey theme, selectable OpenRouter free models (and optional NVIDIA models), and streamed Markdown rendering.

## How to develop

Run these commands from the repository root:

```bash
cd app/frontend
npm install
npm run build
cd ..
uv run python manage.py runserver
```

Every time you edit the React or CSS source, run `npm run build` in `app/frontend`. The build writes `app.js` and `app.css` under `app/members/static/members/dist/`. Django serves these files locally.

## Structure

- `src/main.jsx` — landing page, login, and signup.
- `src/Chat.jsx` — conversation sidebar, new chat, model picker, streaming display.
- `src/chatApi.js` — authenticated HTTP requests and SSE stream parser.
- `src/style.css` — permanent dark theme and Markdown styles.
- `app/members/templates/members/ui_base.html` — common Django template shell.

## Routes and backend contract

| Method | Endpoint | Expected result |
| --- | --- | --- |
| GET | `/api/models/` | `{"models":[{"id":"inclusionai/ling-3.2-flash:free","name":"Ling 3.2 Flash (Free)","provider":"OpenRouter"}, ...]}` |
| GET | `/api/conversations/` | `{"conversations":[{"id":1,"title":"My chat"}]}` |
| GET | `/api/conversations/1/` | `{"conversation_id":1,"title":"My chat","messages":[{"role":"user","text":"Hello","model":"z-ai/glm-5.3-flash"}, ...]}` |
| POST | `/api/chat/` | SSE stream of assistant answer |
| GET | `/api/me/` | Authenticated account details |
| POST | `/logout/` | End Django session |

### Send a message

Request JSON:

```json
{
  "message": "Explain how transistors work.",
  "model": "inclusionai/ling-3.2-flash:free",
  "conversation_id": null,
  "request_id": "0d7b64a2-16f8-4f86-9482-1d7e7a27e864"
}
```

The model dropdown defaults to `inclusionai/ling-3.2-flash:free`, and also includes `google/gemma-4-26b-a4b-it:free`. Older NVIDIA model choices remain available. Set `conversation_id` to `null` for a new chat; otherwise supply the existing ID. `request_id` is a unique UUID generated by the frontend for each intended message. Reusing it cannot start another provider call.

Success: `HTTP 200`, `Content-Type: text/event-stream`:

```text
event: meta
data: {"conversation_id": 1, "title": "Explain transistors", "model": "inclusionai/ling-3.2-flash:free"}

event: delta
data: {"text": "## A transistor\n"}

event: delta
data: {"text": "A transistor is a tiny electronic switch..."}

event: done
data: {"conversation_id": 1, "title": "Explain transistors"}

```

The frontend displays Markdown in real time using `react-markdown` and `remark-gfm`. Raw HTML from model output is disabled. The backend never sends model API credentials to the browser.

Before a stream is opened, errors are normal HTTP JSON responses with `{"error":"message"}`. During a stream, errors use an `event: error` frame. In either case, the UI shows an error rather than generating a fake response. A duplicate completed request returns the original result in JSON.

## Notes

- Authentication uses Django's custom session `request.session['user_id']`.
- CSRF is enforced by Django and the frontend sends the CSRF token with POST requests.
- Conversation and reply data come from Django, not demo fixtures.
- AI model IDs, provider rates, and keys are server-side concerns. `services.py` routes to OpenRouter or NVIDIA using `OPENROUTER_API_KEY` or `NVIDIA_API_KEY` from `.env`; `api.py` handles HTTP requests and ownership checks.
- See the repository-level `README.md` for complete installation and run instructions.
